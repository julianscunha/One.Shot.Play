# ADR-002: Multi-Provider com Fallback

## Status
Aceito

## Data
2026-08-17

## Contexto
Precisamos de resiliência contra falhas de APIs externas (IA, TTS, Imagem, Vídeo).

## Decisão
Implementar padrão primary + fallback com timeout e retry automático.

## Alternativas Consideradas

### Circuit Breaker
- Prós: Detecção rápida de falhas
- Contras: Complexidade maior, pode ser overkill para free tier

### Queue de retry
- Prós: Resiliência alta
- Contras: Latência maior, complexidade

### Primary + Fallback (Escolhido)
- Prós: Simples, eficaz, atende requisitos
- Contras: Atraso no fallback (timeout)

## Consequências
- Cada provider tem 2 endpoints configurados
- Timeout configurável (padrão 30s)
- Fallback automático em caso de falha/timeout
- Classificação de erros: TRANSIENT (retry) vs FATAL (alerta)
